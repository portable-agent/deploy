# ADR 0003: единые команды локальной разработки

Статус: принято.

## Контекст

Compose требует несколько env-файлов, profiles и Windows override. Прямой запуск скриптов заставлял
разработчика помнить эти детали и привязывал основной сценарий к конкретной версии PowerShell.
Нужны одинаковые короткие команды для Windows, Linux, локального Compose и будущего k3d-контура.

## Решение

Используем Task 3.53.1 как тонкую кроссплатформенную точку входа. Taskfile не хранит бизнес-логику и
не заменяет Docker Compose, Helm или тестовые инструменты. Он вызывает короткие проверяемые скрипты.

Поддерживаются отдельные сценарии:

- инфраструктура без приложений;
- выбранный сервис с обязательными зависимостями;
- все сервисы;
- состояние, логи, перезапуск и остановка;
- полный локальный E2E;
- явный reset с подтверждением.

Версия Task закреплена в CI. Taskfile валидируется в каждом pull request.

## Последствия

Разработчик изучает один набор команд вместо параметров Compose. Существующие скрипты остаются
обратимо совместимыми, но больше не являются главным пользовательским интерфейсом. Kubernetes-команды
будут добавлены в тот же Taskfile только после появления зелёного k3d developer smoke.
